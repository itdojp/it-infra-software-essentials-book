# 付録A：トラブルシューティングフロー

この付録は、本文の YAML / JSON、スクリプト、API、Git のサンプルで問題が起きたときに、変更を急がず安全に原因を切り分けるための読者向けフローです。製品固有の設定値を当てはめるものではありません。共有環境や本番環境では、組織の手順、承認、担当者の指示を優先してください。

## まず通す判断フロー

1. **安全停止・証拠保全**：更新、再実行、削除、権限変更を止め、時刻、対象、表示されたエラー、実行したコマンド、差分を記録します。
2. **再現/範囲**：個人のローカル検証環境で再現するか、いつからどこまで影響するかを確認します。共有環境での再現操作はしません。
3. **分類**：データ記述言語、shell/Python、API、Git/差分のどれに属するかを選びます。複数に見える場合は、最初に失敗した境界を起点にします。
4. **診断**：read-only の確認で構文、入力、HTTP 応答、差分、ログを観測し、仮説を一つずつ絞ります。
5. **最小対処**：ローカルまたは隔離された検証環境で、原因に対応する最小の変更だけを試します。成功しても、変更範囲を広げる前に再確認します。
6. **再確認/rollback/記録**：期待結果、影響範囲、戻し方を確認し、結果と判断を記録します。安全に戻せない場合は rollback を試みず、担当者へ引き継ぎます。

## 直ちに停止して escalation する境界

次のいずれかに該当したら、調査のための再実行や「試しの修正」を止めます。secret を表示、Issue、チャット、ログへ貼り付けません。

- API キー、トークン、Cookie、秘密鍵、パスワード、接続文字列などの **secret 露出**が疑われる。値を記録せず、組織の手順に従って credential を失効またはローテーションし、セキュリティ担当者へ連絡します。
- 書き込み API、削除コマンド、再起動、デプロイ、設定適用などの **意図しない更新**が始まった、または対象を確定できない。
- **本番/共有環境**、他チームのリソース、顧客データに影響する可能性がある。
- **課金/権限変更**、契約、アクセス制御、外部サービスの利用上限に関わる操作を求められる。

これらは本文の基礎操作だけで自己解決する範囲ではありません。作業を止め、時刻、対象、観測結果、既に実行した read-only 操作だけを添えて、責任者または担当チームへ escalation します。

## 症状別route

### JSON / YAML が読めない、または設定が意図どおりに解釈されない

- **観測対象**：パーサーのエラー位置、行番号、キー名、インデント、引用符、配列・オブジェクトの構造。
- **read-only確認**：対象ファイルのコピーを開き、構文検証または schema / lint をローカルで実行します。秘密情報を含む行はマスクし、値を共有しません。
- **次の判断**：最初の構文エラーを直すと同じ場所で再現するか、構文は通るが型・キー・期待値が違うかを分けます。
- **対処**：ローカルのコピーで、インデント、区切り、引用、キー、データ型を一箇所ずつ最小修正します。自動整形の結果も差分で確認します。
- **停止/escalation**：本番設定、secret、複数システムで共有される設定、適用対象を特定できない変更は停止します。
- **関連章**：[第2章：データ記述言語の基本と実践]({{ '/chapters/chapter02/' | relative_url }})

### shell / Python が失敗する、または想定外の対象を操作しそうになる

- **観測対象**：終了コード、標準出力・標準エラー、実行ディレクトリ、入力ファイル、環境変数、対象パス。
- **read-only確認**：コマンドのヘルプ、`pwd`、対象の一覧、Python の構文検査、Git 管理下のスクリプト差分を確認します。破壊的なサブコマンドは実行しません。
- **次の判断**：構文・依存関係の失敗か、入力値・パス・権限の不一致か、実行対象の選択ミスかを分けます。
- **対処**：一時ディレクトリまたはテストデータで、対象を allowlist 化し、dry-run 相当または表示だけの処理から確認します。タイムアウトと失敗時の終了条件を明確にします。
- **停止/escalation**：削除、再起動、権限変更、外部コマンド実行、共有パスへの書き込み、対象が空または広すぎる場合は停止します。
- **関連章**：[第3章：スクリプト言語による自動化の初歩]({{ '/chapters/chapter03/' | relative_url }})

### API の 4xx / 429 / 5xx / timeout が返る

- **観測対象**：HTTP メソッド、URL のホスト名とパス、ステータスコード、相関 ID、再試行回数、応答ヘッダー、タイムアウト設定。認証値や本文の secret は記録しません。
- **read-only確認**：ドキュメントと照合し、読み取り専用の endpoint またはヘルスチェックで接続、認証状態、入力形式を確認します。429 では応答ヘッダーの待機指示を確認します。
- **次の判断**：4xx は認証・認可・入力・対象指定、429 は利用制限、5xx / timeout はサービス側またはネットワーク側の一時障害として分けます。
- **対処**：4xx は最小権限と入力形式を見直し、429 は待機と指数バックオフを用い、5xx / timeout は冪等な読み取り確認に限定して記録します。書き込み要求の無条件再試行はしません。
- **停止/escalation**：課金対象の再試行、権限昇格、書き込み要求の重複実行、外部サービス障害、credential 不明または露出の疑いは停止します。
- **関連章**：[第4章：API によるインフラ連携]({{ '/chapters/chapter04/' | relative_url }})

### Git / 差分で競合した、または変更内容を説明できない

- **観測対象**：現在のブランチ、作業ツリーの状態、差分、競合箇所、直近のコミット、変更対象ファイル。
- **read-only確認**：`git status`、`git diff`、`git diff --staged`、`git log --oneline` で、未追跡ファイルと意図しない変更を分けて確認します。secret が含まれそうなファイルは内容を共有しません。
- **次の判断**：自分の未コミット差分か、他者の変更との競合か、生成物・設定・実装のどの差分かを分けます。
- **対処**：ローカルブランチで差分を小さくし、競合は両方の意図を確認してから解消します。変更はレビュー可能な単位にし、テスト結果と戻し方を PR または作業記録へ残します。
- **停止/escalation**：共有ブランチへの強制 push、履歴書き換え、戻し方が不明な差分、秘密情報を含む可能性がある変更は停止します。
- **関連章**：[第5章：インフラ運用を支えるその他のソフトウェア知識]({{ '/chapters/chapter05/' | relative_url }})

## 記録テンプレート

記録には、日時、環境区分（ローカル/検証/共有/本番）、症状、観測した事実、実施した read-only 確認、選んだ判断、最小対処、再確認結果、rollback の要否、escalation 先を残します。推測と事実を混在させず、secret や個人情報は記録しません。
